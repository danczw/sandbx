What sandbx claims to enforce

Ten controls, on Linux 6.10+ with unprivileged user namespaces, for any command run through SandboxedCommand. Default-deny, fail-closed.

The split to keep straight

seccomp: the doorwayLandlock: the shelves
Seeswhich syscall, and its plain-number argumentswhich file, or which TCP port, is actually accessed
Can'tread a path or address behind a pointerpolice mounting, UDP, kernel code, …
Jobremoves whole kinds of requestjudges the ordinary ones case by case
Examplemount → blocked; open → passesopen("file.txt") → under a grant?

Namespaces are the third tool: a private copy of something the machine normally shares (network, process numbers, file-tree view).

The ten rows

1Filesystem Landlock

What
Which paths the command may read, write, run. Granted separately: read ≠ write ≠ execute; --allow-exec = read + execute; nothing else confers execute. (CLI --allow-write also grants read.)
Detail
ABI 5 minimum (Linux 6.10); uses the newest level the kernel enforces in full; partial enforcement → refuse.
Say
"Landlock in the kernel, three separate rights, and it runs only if the whole ruleset is enforced."

2Entry point SHA-256 over an open file handle

What
--pin-sha256: the one program launched must match a fingerprint of its bytes.
Detail
Hashed through a file descriptor, then run through that same descriptor: no re-lookup of the name, so no swap between check and run (TOCTOU). Refuses #! scripts and unreadable programs.
Limit
Covers the entry point only. Pinned python3 still runs any script.
Say
"--allow-exec names a path; the pin names the bytes."

3Network empty netns · or Landlock ports + seccomp

What
Default: empty network namespace, nothing to connect to. --allow-network PORT: TCP to that port only.
Detail
Port mode shares the host network; seccomp blocks what Landlock can't police: UDP, raw sockets, other protocols, IP tunnels, TCP_ULP, TCP Fast Open.
Limit
Port ≠ host: 443 is open to every host. Stops SSH/database access, not HTTPS exfiltration. DNS, QUIC, HTTP/3 break; localhost reachable.
Say
"A port allowlist, not a destination allowlist, and documented as such."

4Name resolution private /etc via mount namespace

What
--allow-dns NAME: only listed names resolve; others fail at once.
Detail
sandbx resolves the names first, then bind-mounts read-only hosts (just those), nsswitch.conf (no DNS), resolv.conf (no server) over /etc, in the command's view only. Grants no path.
Limit
Names, not destinations: a bare IP bypasses it. Refuses combos leaving a DNS server reachable. Ubuntu's AppArmor restriction → run refused.

5Unix sockets seccomp · Landlock ABI 9

What
Local mailboxes to other programs (docker.sock, ssh-agent, session bus). Denied by default.
Detail
seccomp blocks socket(AF_UNIX) and connectionless socketpair (could be re-aimed outside); connected pairs allowed (both ends inside).
Limit
--allow-unix-sockets is all or nothing below ABI 9 (Linux 7.1): /run/docker.sock reachable with no grant naming it. No kernel shipping today is at ABI 9.

6Environment cleared at every process start

What
Only named variables cross. CLI default seven: PATH HOME TERM LANG LC_ALL LC_CTYPE TZ, plus --allow-env NAME, plus constants sandbx sets.
Detail
The kernel hands the environment over before any lock applies, so it's enforced by not passing it. All three spawns go through spawn::command; stage 2 refuses an unexpected variable.
Limit
An allowed name passes its full value. ANTHROPIC_API_KEY refused on agent subcommands.

7Syscalls seccomp denylist

What
Process inspection, namespace creation, mounting, loading kernel code, keyring, io_uring, userfaultfd, memfd_create, reboot/swap.
Detail
Answers EPERM (looks like a permission error, not a crash). clone3 → ENOSYS so threads fall back to the filterable clone. Foreign architecture / x32 → killed.
Why io_uring
Submits work via shared memory, not syscalls, so it would bypass seccomp's rules (Landlock still checks the file).

8Process state capset · prctl · rlimit

What
Empty effective / permitted / inheritable / ambient capabilities; no_new_privs; RLIMIT_CORE = 0 (no core dumps).
Detail
no_new_privs: launching a program never grants more power, so setuid sudo starts as an ordinary user. Required before installing seccomp or Landlock without admin rights.
Limit
Bounding set cleared best-effort (AppArmor strips the needed capability) → degraded audit record; harmless given the rest.

9Process lifetime PID namespace, sandbx's own init

What
Everything the command started dies when the call ends, setsid included.
Detail
When a namespace's init (process #1) exits, the kernel kills everything in it. Init is helper stage 2, never the command, which could switch off its own shutdown paths. Ends via group kill on timeout, or PR_SET_PDEATHSIG if stage 1 dies.
Limit
Only time is bounded: no CPU, memory or process-count cap. WSL2 measured not delivering the death signal (#272); a survivor is still fully locked.

10Process signalling PID namespace

What
Can't signal, or even name, any process outside its namespace.
Limit
/proc shows host PIDs (remounting needs mount, which is blocked). A compatibility quirk, not a boundary gap.

If asked "what doesn't it protect?"

  • sandbx itself is not sandboxed; neither are its dependencies.
  • Write access to a project tree = write to .git/hooks, Makefile, … which run outside the sandbox later.
  • Approval is not enforcement; --approve run asks nothing per call.
  • Sessions are plaintext on disk; a stored key is plaintext at 0600.
