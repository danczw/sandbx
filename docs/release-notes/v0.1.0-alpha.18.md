**Nothing a command can reach changes in this release: no flag, no policy, no
enforcement path.** It is phase 2 of moving the workspace onto the Google Rust
style guide (#328, tracked as #331), nineteen pull requests of pure module moves
so that a module holding submodules now holds only `mod` lines and re-exports.
`SECURITY.md`'s claims, non-claims and known weaknesses are unchanged, and no
item's visibility widened anywhere in the phase — five of the moves narrowed
what a sibling module can reach.

**Where the code lives moved, but nothing was deleted.** Seventeen parent
modules became re-export shims, so a link to `core/src/policy.rs` or
`cli/src/agent.rs` still resolves and lands on ten lines of re-exports instead
of the code, which is in `policy/sandbox.rs` and `agent/run.rs`. Twenty-one
files are new. Only three links actually broke, all test files hoisted to
`#[path]` siblings: `compact/tests.rs`, `agent/gate/tests.rs` and
`agent/prompt/tests.rs` are now `compact_tests.rs`, `gate_tests.rs` and
`prompt_tests.rs`. `context/guide-repo-map.md` is the index to where everything
went, and each crate's onboarding chapter was re-pointed with it.

**Three public-API baselines moved without a widening, which is worth knowing
before you read them as one.** `cargo-public-api` records a type's *declaration*
path, so moving a type one module deeper re-renders it in the baseline of every
crate whose public signatures name it — eleven lines across `sandbx-agent`,
`sandbx-cli` and `sandbx-tools`, for instance `policy::SandboxPolicy` becoming
`policy::sandbox::SandboxPolicy`. No item was added, removed or made more
visible; `sandbx-core`'s and `sandbx-providers`' own baselines are untouched.
The consequence for anyone extending this work: grepping the moved crate's own
baseline does not detect it, so run `.github/scripts/public-api.sh` and commit
the result rather than reasoning about whether a move is visible.
