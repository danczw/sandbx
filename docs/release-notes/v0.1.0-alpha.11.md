**An exec grant names a path; `--pin-sha256` names the bytes** (#146). An
`--allow-exec` grant runs whatever is at that path when the command starts, so
paired with write on the same tree — the usual build-then-run flags — a command
can choose its own binary. Pass `--pin-sha256 "$(sandbx hash ./target/debug/tool)"`
and a mismatch refuses the run before anything executes, closing the trail as
`failed reason=pin_mismatch`. Nothing changes without the flag.

It pins the entry point only: the one program sandbx executes, which must be an
absolute path, and nothing that program then spawns — a pinned `/usr/bin/python3`
is still arbitrary code, and the `/usr`, `/bin`, `/lib` floor every run gets is
unpinned. `SECURITY.md` states the limit; `sandbx hash PATH` is a new subcommand
that confines nothing and prints one digest.
