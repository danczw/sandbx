**An exec grant names a path; `--pin-sha256` names the bytes** (#146). An
`--allow-exec` grant runs whatever is at that path when the command starts, so
paired with write on the same tree — the usual build-then-run flags — a command can
choose its own binary. Pass `--pin-sha256 "$(sandbx hash ./target/debug/tool)"` and
a mismatch refuses the run, as `failed reason=pin_mismatch`, before anything
executes. Nothing changes without the flag.

It pins the entry point only: the one program sandbx executes, which must be an
absolute path it can read, and nothing that program spawns — a pinned
`/usr/bin/python3` is still arbitrary code, and a `#!` script is refused rather
than run unchecked, so pin the interpreter. `SECURITY.md` states the limit, every
spawn record now carries `pinned`, and `sandbx hash PATH` prints one digest.
