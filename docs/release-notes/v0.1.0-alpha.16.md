**A sandboxed command could outlive its timeout and a killed supervisor, and the namespace's init
is now sandbx's own process** (#272). The command used to be PID 1, the process the kill chain
ends, and it could shed both links: `setsid` left the group sandbx kills, and an `exec` from a
second thread dropped the per-thread parent death signal with no `prctl` at all. Measured: such a
command outlived a 1s timeout and a `SIGKILL`ed supervisor alike, while sandbx reported it killed.
Stage 2 now spawns the command and stays as a single-threaded, non-dumpable init that never execs,
so neither link can be taken from it. **What a command sees changes**: it is PID 2 with parent 1,
and an unhandled `SIGTERM` aimed at it now ends it instead of being ignored. A signalled command
still exits `128 + n`, but a library caller's `ExitStatus::signal()` is no longer set. One survivor
remains possible, on an untimed call whose kernel does not deliver the init's parent death signal,
as #272 measured on WSL2; `SECURITY.md` says so.

**Model output can no longer hide or erase sandbx's own lines.** Under `--show-thinking` a
reasoning delta reached stderr verbatim, so `\x1b[8m` concealed every `sandbx:` line after it and
`\x1b[A\x1b[2K` could erase the gate's verdict; control and invisible characters are now replaced
with U+FFFD (#239). Six combining overlays that drew the TUI's gutter mark on a space, U+20D2 among
them, are replaced too (#280). A `tui` turn that lost its terminal no longer forks `tput`, found
through `PATH`, from sandbx's unsandboxed process (#269); crossterm's key reader still can when a
resize races a hangup, which `SECURITY.md` now states.

**A resumed session reads the transcript in the directory it vetted** (#317): every open is an
`openat` on the vetted root's descriptor, closing a rename window between the check and the read.
Its owner must now be both the real and the effective uid (#318), so a setuid install refuses where
it used to replay files its caller chose. rustls moves to 0.23.46 and rustls-webpki and
webpki-root-certs with it, for RUSTSEC-2026-0346 to -0349, -0382 and -0383. `sandbx-providers`
loses `MockProvider` and its `mock` feature (#305), `ProviderError`'s retry classification (#306)
and `AnthropicClient::from_env` with `resolve_api_key` (#301); a key now enters only through
`AnthropicClient::new`. The CLI's flags, key sources and exit codes are unchanged.
