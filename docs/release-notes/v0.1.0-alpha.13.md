**`--allow-dns NAME` bounds which names a command can resolve** (#145). sandbx resolves
each name in the harness before the command starts and gives the command a hosts file
holding those addresses and no nameserver at all, so a name the flag did not list does
not resolve; a run without the flag resolves exactly as it did before. The files are bound
in a mount namespace of the command's own: the host's `/etc` is untouched, and read-only to
the command even under `--allow-write /etc`. It is the one flag that makes a policy smaller:
resolution no longer needs `--allow-read /etc`, and it works under musl and for a static
binary, where `--dns-over-tcp` never did. A symlinked `/etc/resolv.conf`, as
systemd-resolved leaves, gets no read rule: the command gets `EACCES` there rather than
sandbx's body unless another grant reaches it, the bound resting on `nsswitch.conf` under
glibc and the port allowlist under musl. It bounds resolution and not connection — an
address the command already holds is still reachable — so every shape leaving a nameserver
that could answer for any name is refused: with `--dns-over-tcp`, a bare `--allow-network`,
`--allow-unix-sockets` (nscd answers over one), 53 in the port list, or no
`--allow-network` at all. It needs a host where an unprivileged user namespace may mount,
and refuses the run where one may not. Embedding: `SandboxPolicy` gained `allow_dns` and
`allowed_dns_names`, `Spawned` a `dns_names` count.

**A turn that runs out of rounds is now stored and resumable** (#188). `--session` keeps
the prompt, the round that asked for a tool and its result, so the tokens the cap spent
and the edits it made survive it — including under `--no-wrap-up`, and when the wrap-up
round fails or answers with another tool call, where the run previously left the
transcript unchanged. `Session::pending_call()` is new, and `SessionError::IncompleteTurn`
now means a prompt nothing answered rather than a turn not ending on a reply.

**A path grant now crosses into the sandbox helper resolved, absolute and pinned to its
object** (#205, #212). The helper refuses the run if a granted path opens as a different
one, or holds a different object — a real directory renamed over a granted one no longer
passes; the six in-process tools compare the path alone, which #212 carries. A sandboxed
command also starts in a directory its policy grants, not sandbx's own (#191).
