**`--allow-dns NAME` bounds which names a command can resolve** (#145). sandbx resolves
each name in the harness before the command starts and gives the command a hosts file
holding those addresses and no nameserver at all, so a name the flag did not list does
not resolve; a run without the flag resolves exactly as it did before. The files are
bound into a mount namespace of the command's own, so the host's `/etc` is untouched and
read-only to the command even under `--allow-write /etc`. It is the one flag that makes a
policy smaller: resolution no longer needs `--allow-read /etc`, and it works under musl
and for a static binary, where `--dns-over-tcp` never did.

It bounds resolution and not connection — an address the command already holds is
reachable on any allowlisted port as before — so the shapes where a nameserver would
still answer for every name are refused rather than silently weakened:
`--allow-dns` with `--dns-over-tcp`, with a bare `--allow-network`, with 53 in the port
list, or with no `--allow-network` at all. A value that is no resolvable name, an IP
literal included, is a usage error. Embedding the crates: `SandboxPolicy` gained
`allow_dns` and `allowed_dns_names`, and the `Spawned` audit record gained `dns_names`,
a count and never a name.
