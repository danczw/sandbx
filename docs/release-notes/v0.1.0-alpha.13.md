**`--allow-dns NAME` bounds which names a command can resolve** (#145). sandbx resolves
each name in the harness before the command starts and gives the command a hosts file
holding those addresses and no nameserver at all, so a name the flag did not list does
not resolve; a run without the flag resolves exactly as it did before. The files are
bound into a mount namespace of the command's own, so the host's `/etc` is untouched and
read-only to the command even under `--allow-write /etc`. It is the one flag that makes a
policy smaller: resolution no longer needs `--allow-read /etc`, and it works under musl
and for a static binary, where `--dns-over-tcp` never did. It bounds resolution and not
connection — an address the command already holds is reachable on any allowlisted port as
before — so the shapes where a nameserver would still answer for every name are refused
rather than silently weakened: with `--dns-over-tcp`, with a bare `--allow-network`, with
`--allow-unix-sockets` (nscd answers over one, asked before `nsswitch.conf` is read), with
53 in the port list, or with no `--allow-network` at all. It needs a host where an
unprivileged user namespace may mount, which a kernel restricting them does not give; such
a run is refused, never left unbounded. Embedding the crates: `SandboxPolicy` gained
`allow_dns` and `allowed_dns_names`, and `Spawned` gained `dns_names`, a count not a name.

**A turn that runs out of rounds is now stored and resumable** (#188). `--session` keeps
the prompt, the round that asked for a tool and its result, so the tokens the cap spent
and the edits it made survive it — including under `--no-wrap-up`, and when the wrap-up
round fails or answers with another tool call, where the run previously left the
transcript unchanged. `Session::pending_call()` is new, and `SessionError::IncompleteTurn`
now means a prompt nothing answered rather than a turn not ending on a reply.

**A path grant now crosses into the sandbox helper resolved and absolute**, and the helper
refuses the run if a granted path opens as a different one (#205). The readback compares
the path and not the inode, so the seam is not substitution-proof; `SECURITY.md` says so
as a non-claim and #212 tracks closing it. A sandboxed command also starts in a directory
its policy grants rather than inheriting sandbx's own (#191).
