**`--allow-dns NAME` bounds which names a command can resolve** (#145). sandbx resolves
each name in the harness before the command starts and gives the command a hosts file
holding those addresses and no nameserver at all, so a name the flag did not list does not
resolve; a run without the flag resolves exactly as it did before. The files are bound in a
mount namespace of the command's own, so the host's `/etc` is untouched and stays read-only
even under `--allow-write /etc`. It makes a policy smaller — resolution no longer needs
`--allow-read /etc`, and it works under musl and for a static binary, where `--dns-over-tcp`
never did — and it bounds resolution, not connection, so every shape leaving a nameserver
that could answer for any name is refused. A path grant now also crosses into the helper
resolved, absolute and pinned to its object (#205, #212): the run refuses if a granted path
opens as a different one or holds a different object, so a real directory renamed over a
granted one no longer passes — the six in-process tools compare the path alone, which #212
carries. A sandboxed command starts in a directory its policy grants, not sandbx's own
(#191).

**`--approve call` asks the operator before each call that writes or runs a program** (#165,
#169). The question goes to the controlling terminal: `y` for the one call, `n` to refuse
it, `a` for every later call to that tool. `--allow-tool` stays the ceiling — a tool it
never approved is refused unasked — read-only calls are never asked about, and a run with no
terminal to ask on is refused rather than served the weaker argv answer. Every call is
reported once it has settled, so a call the gate approved and the policy then refused no
longer reads as one that ran.

**A turn that runs out of rounds is stored and resumable** (#188). `--session` keeps the
prompt, the round that asked for a tool and its result, so the tokens the cap spent and the
edits it made survive it, including under `--no-wrap-up` and where the wrap-up round itself
fails. Embedding: `SandboxPolicy` gained `allow_dns` and `allowed_dns_names`,
`Session::pending_call()` is new, and the provider request is a neutral `Prompt` with no wire
format of its own — `max_tokens` is `max_output_tokens`, `input_schema` is `schema`, and a
turn's signed reasoning is replayed within it (#59, #85).
