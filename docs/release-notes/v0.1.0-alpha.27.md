**Consecutive read-only calls in one round now run together.** A `read`, `ls`,
`grep` or `find` beside another starts without waiting for it, and a `write`,
`edit` or `bash` still runs alone, after the reads before it settle, so no writer
is ever in flight beside another call. Nothing runs while a call waits for
approval: a gate that asks about reads is asked about every read in a run of them
before any starts. A stop during those reads ends the round before a `write`
behind them is asked about. `tui` shows one running row per call in flight
(#242).

**`SECURITY.md` now prices a seccomp notifier for per-host egress, and declines
it.** It could read the address behind `connect`, but it bounds addresses, not
hosts, so an allowlisted API on a shared CDN edge admits every site on that edge
(#512). Nothing in the sandbox changes. Nothing breaks for a user, but
`sandbx-tui-transcript`'s `Transcript::run` and `settle` now take the call's
`tool_use` id, so an embedder calling either must pass it.
